## Corrected requirements

- Ordinary tasks should finish in seconds or a few minutes. Twenty minutes is a hard maximum for an individual task, including its retries, not a target or a fresh allowance for every attempt.
- Prefer completion of the entire agreed chapter checkpoint in less than thirty minutes. The overall ceiling is less than one hour, including research, delegation, writing, review, correction, generation and packaging.
- The project clock is cumulative across automatic loop wakeups and retries. Dividing work into more tasks must not reset or multiply its allowance. Time explicitly spent waiting for Lucas's requested review is outside execution time and must be reported separately.
- When a loop is authorized and no explicit review hold applies, continue useful refinement without requiring Lucas's feedback after every checkpoint. Feedback is occasional, not the normal execution gate.
- Never call incomplete or unverified work complete merely to meet a time limit. If the ceiling cannot be met, deliver the verified checkpoint, name the concrete unresolved blockers and stop automatic expansion. Do not quietly run another hour.

## Proposed execution design

### One change list and one baseline

Start from the existing article, verified inventory, current evidence and latest accepted layout. Classify each requested change as factual, missing coverage, presentation or optional polish. Keep one concise finding list with the exact passage, required correction, source and owner. Do not create another backlog or a separate task for every paragraph.

Preserve unchanged article sections and native references mechanically. Writers return targeted section replacements or edits against that baseline, not a new version of the whole chapter. A genuine restructuring must retain the verified inventory and state its exact replacement boundary.

### Two independent Luna lanes and a working parent

Retain the maximum of two concurrent writers. Assign disjoint sections or topics, sized for completion in a few minutes rather than filling the twenty-minute allowance. Each writer receives only the relevant article, changes and compact source evidence. Reuse a session while its context remains useful; use a compact handoff rather than repeatedly carrying a large transcript that requires compaction.

Each lane resolves its own directly relevant factual gaps using already collected primary evidence. The parent should not become a prerequisite for every source lookup. If a gap cannot be settled quickly, return the exact unresolved statement and evidence needed while completing the independent edits. Do not use guessed behavior or delete a functional family to conceal the gap.

The parent works concurrently on integration readiness, automated coverage and language checks, shared factual decisions and packaging. It does not reread every unchanged page, rewrite worker prose cosmetically or build a new validator for every batch. Save and hand off each completed topic immediately, without waiting for its lane's entire assignment.

### Integrate in small completed increments, verify the whole checkpoint once

Before accepting an increment, use existing cheap checks for unexplained identity loss, exact bilingual references and parseability. Unchanged sections pass through byte-identically. A failed increment stays isolated; it does not hold back unrelated completed increments.

Review actual gameplay instructions and changed presentation, then make one consolidated correction pass. Small remaining edits are parent-owned patches, not another full writer restart. Reopen only changed content and its real cross-page effects.

After content is ready, run the existing chapter-wide checks together, generate once, export and verify archive bytes. Rerun only checks affected by a subsequent fix. Preserve the distinction between source and archive checks, actual registry evidence and in-game rendering. Do not invent a successful test or weaken a preservation gate.

### Deliver early without making every checkpoint a feedback gate

Aim to complete the usable chapter checkpoint around minute twenty-five and preferably before minute thirty. These are ceilings and scheduling checkpoints, not waiting periods. If the work finishes earlier, deliver immediately.

If incomplete at minute thirty, publish the current verified preview with exact remaining blockers and continue only necessary corrections within the remaining overall budget. Do not spend the contingency on optional wording or new research scope. Finish or explicitly stop before the one-hour ceiling. Any incomplete delivery remains clearly labeled.

Do not silently install known regressions into the playable preview. When incomplete drafts are useful for inspection, keep them clearly separated from integrated content. Always explain exactly which version the game loads.

## Concrete execution runbook

### Dispatch contract

Before dispatch, put only the following into each assignment: exact owned topic and section names, the current baseline fragment, protected native identities, requested changes, relevant verified facts with source locations, unresolved questions, output path and deadline. Keep global rules in the shared contract rather than pasting the entire conversation. Assign one or two related topic pairs at a time, chosen to finish in a few minutes. Do not create a new Kanban card or planning document for every section.

The writer changes only named sections. It assembles its returned topic fragment by copying all other sections unchanged. Every changed factual claim cites its source in the evidence file. It returns a fragment, a compact changed-section list and any concrete blockers. This uses the current fragment workflow, not a new authoring framework.

### What happens concurrently

| Actor | Starts with | Produces | Does not wait for |
| --- | --- | --- | --- |
| Luna lane one | First independent group of corrections and its source sheet | A saved topic pair as soon as it is ready | Lane two or a parent lookup for an unrelated topic |
| Luna lane two | Second independent group of corrections and its source sheet | A saved topic pair as soon as it is ready | Lane one or completion of the whole chapter |
| Parent | Existing checks, source tree and packaging route | Accepted increments, one shared finding list and export readiness | Both writers finishing before checking the first returned increment |

The parent gives the next independent group to the first free lane, retaining the two-writer ceiling. Do not leave a lane idle while conducting unrelated parent research. Do not dispatch another group when the overall deadline leaves insufficient time for review and export.

### Fast research decision tree

1. If the fact is already verified for the selected release, reuse its source location. Do not search again.
2. If a fact changed or is genuinely missing, read the specific maintained instruction, selected Ponder lesson, recipe or tracked setting that answers it. Batch independent reads in one tool turn.
3. If those sources conflict, inspect only the consuming method or registration needed to settle that conflict. Do not dump an entire mod's classes or build a new inspection tool for a single sentence.
4. If the specific gap remains unresolved after a short focused lookup, continue independent edits and record the exact blocker. Keep the existing verified content instead of substituting a guess or deleting the device. A required unresolved instruction prevents final acceptance of that topic, not progress on every other topic.

### Acceptance and repair contract

As soon as a topic pair returns, run the existing fragment checker and inspect its coverage report. The current checker reports missing identities without making every disappearance an automatic failure, so the parent must explicitly reject any unexplained loss. Match dispositions to actual retained destinations, verified identifier corrections or specific material-input retirements. A writer's statement that coverage is complete is not the gate.

Review the changed factual claims, both languages and the changed presentation only. Keep unchanged sections byte-identical. If a small defect remains, patch that exact paragraph or table cell in a separate parent-reviewed copy. If the output is a broad regression, reject it and reuse the last good baseline, not the bad rewrite as the next starting point. Do not repeatedly ask the writer to regenerate the entire page. Repeated omissions of the same kind trigger a method adjustment before more work is dispatched.

Once the chapter's necessary edits are complete, run the existing whole-checkpoint checks together and export through the existing package route. Do not rerun the full chapter suite after each paragraph or postpone preparing the export command until all writing is finished.

| Latest checkpoint | Expected state |
| --- | --- |
| Minute three | Baseline and concise change list ready; both useful writing lanes already working |
| Minute twelve | Main edits returned or landing incrementally; parent checks and integration are happening alongside writing |
| Minute twenty | Necessary factual corrections consolidated; content converging without another broad rewrite |
| Minute twenty-five | Intended complete review archive and concise handoff |
| Before minute thirty | Preferred entire-checkpoint completion; otherwise publish measured progress and only concrete blockers |
| Before one hour | Stop execution with a verified artifact and an honest final or incomplete status |

Individual tasks normally take seconds to a few minutes. No task receives a default twenty-minute reservation. A task that stops producing useful progress is narrowed or stopped promptly; no individual task and its retries may exceed the twenty-minute hard cap.

## Automatic loop rules after the current hold

An authorized loop continues from the finding list and latest integrated artifact. It does not restart planning, rescan the entire mod catalog, reread settled pages or reset the time budget. Fix correctness and missing coverage first, then presentation, then optional polish only if time remains.

Only report a new artifact, meaningful completed work, a changed completion estimate backed by measurements, or a genuine blocker. Delayed worker notices are not new progress. Do not keep notifying Lucas of unchanged rejected drafts.

If required quality is met, export and stop the loop as complete. If the overall cap is reached with unresolved requirements, export the safe checkpoint and stop automatic expansion with the blocker explicit. Human review is required for chapter acceptance and merging, not for every intermediate correction.

## Measurement and quality safeguards

Record stage start and finish, active writer windows, review and integration duration, waiting and completed topic counts. Measure the critical path, not the sum of overlapping worker times. Preserve the previous timing report as historical evidence; the new method has not yet been exercised and must not be described as a proven speed improvement.

The completion gate remains factual support for substantive instructions, meaningful coverage, bilingual meaning and native-reference parity, appropriate visuals, valid components, protected unrelated content and a verified downloadable archive. Time caps do not waive any gate.
